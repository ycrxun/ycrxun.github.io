Wayline：给技术博客做一条真正可读的路径

Wayline 不是一套更花哨的博客皮肤，而是围绕阅读路径、内容层级和长期写作重新组织的 Hugo 主题。

一个用了很多年的博客主题，最后往往会变成这样：页面还能打开，文章还能发布，但每次想加一点新东西，都像是在旧房子里找一根不知道通向哪里的电线。

旧主题的问题通常不是“不好看”这么简单。

真正的问题是，文章、归档、照片、个人介绍和搜索各自属于不同的年代：有的样式来自模板默认值，有的交互只是临时补丁，有的页面已经很少被打开，却又不能删除。内容仍然在增长，界面却没有形成一套稳定的阅读逻辑。

Wayline 就是从这个状态里重新整理出来的一条路径。

路径不是装饰

“Wayline”这个名字来自道路、轨迹和方向感。

但主题里的路径不是首页上一条装饰性的线，而是贯穿整个阅读体验的结构：

  • 首页用精选与最近更新建立第一层方向；
  • 归档按时间展开，而不是简单堆成卡片墙；
  • 文章页强调正文、目录和连续阅读；
  • 影像作为独立内容源，不再从技术文章里自动抓图；
  • 关于页既是个人信息，也是一份可打印的简历。

同一套视觉语言在这些页面之间重复，但每个页面解决的问题不同。

好的主题不应该让所有页面长得一样。它应该让读者在进入不同页面时，仍然知道自己还在同一个地方。

三种阅读环境，而不是三套皮肤

Wayline 提供深色、浅色和暖纸色三种模式。

它们不是简单换几个背景颜色：

  • 深色模式适合夜间阅读和代码；
  • 浅色模式强调清晰、中性的信息层级；
  • 暖纸色降低蓝光和对比刺激，适合长时间阅读。

配色模式会保存到本地。字体也全部自托管，包括 Space Grotesk、Noto Sans SC、LXGW WenKai 和 JetBrains Mono，不依赖第三方字体 CDN。

这部分看起来属于“视觉细节”，但它实际决定了主题能不能长期使用。一个技术博客可能被阅读十分钟，也可能被重新打开五年。稳定、离线可用、没有外部运行时依赖，比一次性的视觉新鲜感更重要。

技术文章首先需要被读清楚

技术博客的主要内容通常不是图片，而是文字、代码、链接、列表和结论。

所以 Wayline 在文章页里优先处理这些基础问题：

  • 正文有明确的阅读宽度和行高；
  • 标题使用更适合中文长文的圆润显示字体；
  • 代码块支持复制、语言标识和横向滚动；
  • 目录会跟随当前章节；
  • 图片不会撑破正文；
  • 元信息保持克制，不抢占标题与正文的层级。

这些能力单独看都很普通，但组合起来决定了一篇文章是否“顺着读得下去”。

技术博客并不需要每一屏都制造惊喜。更多时候，它需要的是读者能在半小时后重新回来，迅速找到自己停下的位置。

归档应当是一条时间线

很多博客归档最终会变成按年份分组的链接列表。

它能用，但它没有表达时间。

Wayline 把归档做成纵向时间轴：年份、月份、分类、标题和摘要沿着同一条轴展开。读者既能看到某一年写了多少内容，也能看到写作主题如何变化。

这也是我后来把“3D 时间线”从 Wayline 中拆出去的原因。

在 3D 世界里，时间线可以是一条可以驾驶的路；但在日常阅读里，用户通常只想快速找到一篇文章。把两者强行放在一起，会让导航承担不必要的交互成本。

影像是独立内容，不是文章附件

旧版相册会从文章配图中自动聚合内容。

这在演示时很方便，在正式写作里却会产生一个明显问题：技术文章里的截图、架构图和报错界面，会被当成“生活影像”展示出来。

现在 Wayline 默认读取独立的 content/gallery/ 目录。每张照片都有自己的页面包：

content/gallery/west-lake-afternoon/
├── index.md
└── cover.jpg

照片可以有独立标题、日期、地点、分类、正文和授权信息。文章归文章，影像归影像。

这并不只是数据来源的变化，而是内容边界的变化。技术博客可以记录工作，但不应该把所有工作截图都自动混进生活相册。

关于页也可以是一份正式文档

Wayline 的关于页采用简历式结构：基础信息、教育经历、工作经历、技能和项目。

页面在屏幕上保持普通网页的阅读体验，同时提供打印样式。点击打印后，会隐藏导航、按钮和背景装饰，把内容收束为单页 A4 文档。

这样同一个页面既可以是“关于我”的公开介绍，也可以是一份随时可以导出的简历，而不需要维护两套完全不同的内容。

为什么最终保持纯 Web

Wayline 曾经包含一个完整的 Three.js 世界。

但博客首页最常见的访问意图仍然是阅读，而不是探索。每增加一个重量级运行时，都会提高首屏成本、移动端失败概率和维护复杂度。

因此最终我把两件事拆开了：

  • Wayline 负责日常阅读、归档、影像和简历；
  • Wayline World 负责空间探索、驾驶、3D 时间线和游戏化阅读。

这不是删掉一个功能，而是承认两个产品有不同的第一入口。

一套主题真正需要稳定的是什么

Wayline 使用 Hugo、Sass 和少量原生 JavaScript。

它没有把博客变成单页应用，也没有要求每篇文章都经过客户端渲染。内容仍然由 Hugo 生成，搜索、主题切换和灯箱只是渐进增强。

对一个长期写作的个人站点来说，这种“普通网站优先”的结构很重要：

  • 搜索引擎能看到完整内容；
  • JavaScript 失效时文章仍然可读；
  • 页面可以静态部署；
  • 主题资源可以独立缓存；
  • 以后更换服务端或部署平台时，不需要重写内容层。

Wayline 想做的不是一套让人第一眼惊叹的模板，而是一条在很长时间里都能走下去的路径。

它不需要每次都给你新的风景，但应该让你知道自己在哪、要去哪，以及下一步从哪里开始。
